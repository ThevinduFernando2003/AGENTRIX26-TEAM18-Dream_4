2. One chat turn (request lifecycle)

flowchart TD
    A["User message"] --> B["emergency.screen()
pure regex — BEFORE any LLM"]
    B -->|emergency| C["Red panel → confirm →
tel:1990 + family ntfy push"]
    B -->|clear| D{"booking intent?"}
    D -->|no| E["detect_reminder() regex"]
    E -->|matched| F["Persist reminder →
sidebar push later"]
    D -->|yes| G["Heuristic route"]
    E -->|no match| G
    G -->|"booking / medicine / report verbs"| I["Skip LLM — instant route"]
    G -->|ambiguous| H["ONE direct LLM JSON call
8 s timeout, no retries"]
    H -->|fail| I
    H -->|ok| I
    I --> J["RAG grounding:
symptom → specialty (never disease)"]
    J --> K["route_request signal →
domain panel runs its agent"]
    K --> L["Agent → SQLite / RAG / push
reply translated si/ta · disclaimer by UI code"]

Say these three principles while pointing:

  1. Emergency first — 32 compiled regexes, ~32 µs per message, zero network, zero API cost (~100,000× cheaper than the LLM call it guards).
  2. Heuristic before LLM — unambiguous intents never wait on a model; the LLM fails fast to the heuristic.
  3. Structural safety — disclaimers, confirm gates, and atomic booking are enforced by code, not prompts.
