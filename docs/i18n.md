# i18n pattern for panels (Sinhala / Tamil / English)

MedBridge AI ships a trilingual UI (`en` / `si` / `ta`). Every visible
string in a panel must render in the logged-in user's preferred language —
**no English leakage**. This doc is the one pattern all panels follow.

Source of truth: [`project/i18n/translate.py`](../project/i18n/translate.py).

## The two tools

```python
from project.i18n.translate import t, translate_dynamic
```

| Function | Use for | Behaviour |
|---|---|---|
| `t(key, lang, **fmt)` | **Fixed** UI wording known at code-time: titles, captions, buttons, table headers, fixed warnings. | Looks up `CATALOG[key][lang]`. Falls back to English, then to the raw key. Supports `str.format` placeholders. **No network, always available.** |
| `translate_dynamic(text, lang)` | **Runtime / data-dependent** free-form text: agent replies, messages built from DB values, anything not fixed at code-time. | Gemini translation, cached per process. **Offline-safe**: returns `text` unchanged when `lang == "en"` or `GEMINI_API_KEY` is absent. |

### Rule of thumb
> **Fixed wording → catalog (`t`). Runtime/data-dependent → dynamic (`translate_dynamic`).**

Never hardcode a user-visible English string in a panel. Never LLM-translate
the disclaimer — it is pre-baked as `disclaimer.footer` so the wording is
reviewable and never drifts.

## Catalog key convention

Keys are dotted and namespaced by panel: `panel.<area>.<thing>`.
Examples already in the catalog:

```python
"panel.medicine.col_total": {"en": "Total (LKR)", "si": "...", "ta": "..."},
"panel.rx.confirm_btn":     {"en": "✅ Yes — search pharmacies", "si": "...", "ta": "..."},
```

- Every key **must** have all three of `en`, `si`, `ta`.
- Keep technical tokens in English across all languages: `GEMINI_API_KEY`,
  `OCR`, `PNG/JPG`, `LKR`, `km`, `Push`, `ntfy.sh`, model ids, drug names.
- Use `{name}`-style placeholders for interpolation; pass them via `t(key, lang, name=…)`.

## Panel usage example

```python
import streamlit as st
from project.i18n.translate import t, translate_dynamic
from project.ui.common import lang_of

def render(user: dict) -> None:
    lang = lang_of(user)                         # how panels read language (reads user["preferred_language"])

    st.subheader(t("panel.medicine.title", lang))            # fixed label
    st.write(translate_dynamic(result.message, lang))        # free-form agent text
    st.caption(t("panel.medicine.matched", lang,
                 names=", ".join(result.matched_names)))     # fixed + interpolation

    table = [{
        t("panel.medicine.col_pharmacy", lang): q.pharmacy_name,
        t("panel.medicine.col_total", lang): f"{q.total_cost:.0f}",
    } for q in result.quotes]
    st.dataframe(table, use_container_width=True, hide_index=True)

    st.markdown(t("disclaimer.footer", lang))   # never translate_dynamic this
```

## Adding a new string — checklist
1. Pick a `panel.<area>.<thing>` key.
2. Add an entry to `CATALOG` with `en` + `si` + `ta`.
3. Render it with `t(key, lang)` (or `translate_dynamic` if it's runtime text).
4. Verify it resolves in all three languages (see below).

## Verifying
```bash
python -c "from project.i18n.translate import t, CATALOG; \
ks=[k for k in CATALOG if k.startswith('panel.')]; \
print(len(ks),'panel keys'); \
[print(k, [t(k,l) for l in ('en','si','ta')]) for k in ks]"
```
Then log in as `demo3`/`demo3pass` (Sinhala) and `demo4`/`demo4pass` (Tamil)
and confirm the panel shows no English.
